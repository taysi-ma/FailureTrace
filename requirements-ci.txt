# Locked test environment — this file IS the venv CI runs in.
#
# Why a lock and not the pyproject ranges: `pip install -e ".[analysis,ollama,dev]"`
# resolves the open ranges (`pandas>=2`, `pytest>=8`, ...) to whatever is newest on the
# day CI happens to run. That silently drifted the runner onto pandas 3.x / numpy 2.5 /
# pytest 9.x while the development venv sits on pandas 2.2.3 / pytest 8.3.4 — CI was
# testing a different environment than anyone develops against. Everything here is
# pinned so a green run means green on the venv, not on an unreviewed upgrade.
#
# Direct dependencies are pinned to the development venv's versions. Transitive pins are
# the resolution of those on CPython 3.13 (see .python-version), captured on linux so the
# file is installable on the runner as well as locally.
#
# NOTE: numpy is the one dependency that cannot match the dev venv. That venv has numpy
# 1.26.4 from conda; 1.26.4 publishes no CPython 3.13 wheels to PyPI (pip offers >=2.1.0
# only), so pip-based CI cannot reproduce it. 2.5.1 is the resolved pin, and pandas 2.2.3
# supports numpy 2.x.
#
# To regenerate after changing a dependency:
#   python -m venv .venv && .venv/bin/pip install -e ".[analysis,ollama,dev]"
#   .venv/bin/pip freeze | grep -v '^-e \|^failuretrace' > requirements-ci.txt
# then re-add this header and review the diff — an unintended major bump should be a
# deliberate, reviewed change, which is the whole point of the file.
